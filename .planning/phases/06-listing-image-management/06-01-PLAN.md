<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Browser file → normalizer | Untrusted bytes, filename, MIME, dimensions, and EXIF enter client processing. |
| Authenticated browser → Storage/metadata | A caller can tamper with keys, listing IDs, count, and order. |
| Public CDN → visitor | Public objects must not expose arbitrary remote URLs or noncanonical retained originals. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-06-01 | Tampering | normalizer/config | high | mitigate | Decode then canonical re-encode; verify output MIME/bytes; source safety ceiling and typed per-file failures. |
| T-06-02 | Elevation | Storage key and metadata writes | high | mitigate | RLS checks `auth.uid()`, key seller prefix, referenced listing ownership, and bucket identity; never trust UI ownership. |
| T-06-03 | Denial of service | concurrent uploads | medium | mitigate | Bucket byte ceiling plus locked DB max-count/order guard and config UX capacity. |
| T-06-04 | Information disclosure | public URL delivery | medium | mitigate | Store only application-owned canonical URLs; no original retention; no arbitrary legacy URL rendering after cutover. |
| T-06-05 | Tampering | cross-service cleanup | high | mitigate | Compensating remove before metadata deletion and retryable failure state. |
| T-06-SC | Tampering | npm install | high | mitigate | Blocking human package-legitimacy checkpoint before every HEIC/HEIF decoder install. |
</threat_model>
